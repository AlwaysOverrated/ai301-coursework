# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Environment | Environment section vs. version/OS/install method in the issue | Passes if they match, or if a mismatch is explained and still valid. Fails if a different setup is used without saying so | required |
| Steps trigger the same bug and are followable by a stranger | Prep/Execution steps vs. the issue's input and command. This check does not apply when the report honestly states it could not reproduce the issue at all -- that outcome is judged only by the Honest conclusion check below | Passes if the same triggering condition is hit with steps a stranger could actually copy and run themselves (a shareable input, a shareable config, a public setup), even with a different command, as long as any change is explained; or if the report honestly reports no reproduction and explains what it tried (skip this check as not applicable, grade it pass). Fails if any essential step or input is private/unshareable (an internal codebase, a private config the reader cannot obtain), even if the report claims it reproduces the same bug, since a reader cannot verify or rerun it | required |
| Same failure shown | Actual output/error vs. the issue's exact error, focusing on whether the specific symptom matches, not just whether both runs involve the same feature area. This check does not apply when the report honestly states it could not reproduce the issue at all -- that outcome is judged only by the Honest conclusion check below, not this one | Passes if the failure shown is the same specific symptom the issue names, or if the report honestly reports no reproduction at all (skip this check as not applicable in that case, grade it pass). Fails only when the report claims to have reproduced something, but what it actually shows is a different error, a different wrong value, or a different kind of failure than the issue names | required |
| Honest conclusion | Analysis/Actual vs. what was really shown | Passes if the conclusion matches the evidence, including an honest "couldn't reproduce" that explains the attempt and what may have differed, in enough detail that a reader can see what was tried. Fails if the report claims more than it showed, including claiming a reproduction when the shown behavior was actually different from the issue, or a bare "couldn't reproduce" with no detail on what was tried | required |
| Comment matches the evidence | Claim comment vs. the report | Passes if it claims only what the report backs up. Fails if it overclaims confidence | required |
| AI use disclosed if the policy specifically asks for disclosure | The claim/repro comment text, checked against the repo's stated AI policy in Repo facts | Fails only when the repo's policy specifically and explicitly requires disclosing that AI was used (naming the tool or extent of assistance) and the comment contains no such disclosure. A policy that only restricts AI-generated content (e.g. "must be written by humans," "low-quality AI content is closed," "AI comments may be hidden") without asking the contributor to disclose AI use is not a disclosure requirement, and this check passes in that case regardless of whether the comment mentions AI. Passes if the repo has no policy, has a policy that does not ask for disclosure, or asks for disclosure and the comment provides it | required |

## Verdict rule

Ready only if every check passes. Any fail, or any unclear on a required check, means hold.
