# Rubric: is this pull request ready to submit?

Each check reads an artifact itself (the diff, the evidence, the description) against the plan, the issue, or the repo's stated asks. None of them grades length, polish, or commit count. The four failure families map to the checks: silent drift (checks 1 and 2), not tested (checks 3 and 4), unreviewable (checks 5 and 6), standards wall (checks 7 and 8).

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff inside plan | The diff's changed files and hunks, read against the plan's stated scope, "files" list, and "not in scope" list, plus any deviation notes. | Every changed file and every substantive hunk is covered by the plan's scope or by a deviation note that names it. Fail if the diff touches code the plan excludes or never mentions (an extra refactor, an extra file, an extra behavior change) with no deviation note. Test files, fixtures, and a changelog entry named in the plan's files list count as covered. | required |
| Plan delivered | The plan's numbered steps and stated fix, read against what the diff actually changes. | Every step of the plan's fix is visible in the diff, or the description or a deviation note says plainly that the step was left out and why. Fail if a planned step is missing from the diff and nothing discloses it. | required |
| Description matches diff | Each claim in the PR description (what changed, "no changes beyond the plan", "tests added", "docs updated", "behavior unchanged") read against the diff and commit list. | Every claim in the description is true of the diff. Fail if the description claims fidelity or coverage the diff contradicts (for example "exactly the plan, nothing else" while the diff has an unrelated hunk, or "tests added" with no test file in the diff). A description that discloses an extra change or a shortfall accurately passes. | required |
| Behavior evidence | The test evidence section's before/after, read against the plan's test plan and the issue's reproduction steps. | The evidence names the observable behavior from the repro, shows the before and the expected-after, and the after is consistent with the fix in the diff. Fail if the evidence is only "tests pass" or "works for me" with no repro re-run, if the before/after is absent, or if the shown output contradicts the claimed fix. | required |
| Repo checks run | The test evidence section, read against the repo's stated checks (the PR template's testing checklist and the repo's own test, lint, and typecheck commands). | Each check the repo or template names was run and its outcome is visible in the evidence, including any that failed or did not run, with a stated reason for each. Fail if a named check has no visible outcome, or if the description ticks a box the evidence does not support. An honestly reported failing check with its reason passes. | required |
| No debris | The diff's hunks and the commit list. | The diff contains no debug leftovers (print or console lines, stray TODOs), commented-out blocks, dead code, or leftover scratch files. Fail if any appears in the diff. | required |
| Reviewable change | The diff's hunks read against the plan's single bounded change. | The fix is visible without hunting: no unrelated hunks, no formatting churn, no reformatting or renaming of code the plan does not touch, no drive-by cleanups riding along. Fail if a hunk unrelated to the plan buries the change, even when it is behavior-neutral. | required |
| Template and disclosure | The repo-facts block's stated PR-template asks and stated AI policy (live: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`), read against the description's sections. | Every section or ask the template names has real content in the description (not left blank, not boilerplate), and where the repo states an AI-use or disclosure policy the description carries the disclosure. Fail if a required template section is missing or empty, a stated checklist item is ignored, or a stated disclosure is absent. A section marked "N/A" with a stated reason counts as filled. | required |
| Maintainer direction | The issue's thread highlights, read against the plan and the diff. | Any explicit direction from a maintainer in the thread (a requested approach, a constraint, a scope limit) is followed or engaged with in the plan or description. Pass if the thread has no such direction. Fail if the PR visibly ignores or contradicts stated maintainer direction. | required |
| Title says the change | The PR title, read against the diff. | A reader of only the title would correctly guess what the diff changes. Fail only if the title names something the diff does not do or omits the main change. | preferred |

## Verdict rule

Accept if every `required` check passes. Reject if any `required` check fails. `unclear` is treated as `fail`: an unverifiable claim is a failing one. `preferred` checks are reported in the summary but never change the verdict.

A disclosed shortfall is not a fail where this rubric says so: a planned step left out with a plain note in the description or a deviation note passes "Plan delivered", and an extra change named in a deviation note passes "Diff inside plan". An undisclosed one fails. If a check passes by its stated condition but feels wrong, it still passes; fix the rubric, not the run.
